# 5.1. Конвертация Intel HEX в BIN

**Язык:** Zig  
**Тема:** Конвертация данных  
**Видео с демонстрацией:** [Ссылка на видео](https://drive.google.com/file/d/1FlASrbR6jASJtglC4tweE55KyDsUJ4ht/view?usp=sharing)

## Описание задачи

Программа преобразует текстовый файл формата Intel HEX в бинарный файл BIN без использования специализированных библиотек.

Реализованы:
- Разбор записей Intel HEX и проверка контрольных сумм.
- Поддержка основных типов записей и расширенной адресации.
- Запись данных по соответствующим адресам.
- Заполнение пропущенных адресов байтами `FF`.
- Обработка некорректных записей и ошибок формата.

Максимальный размер выходного файла — 1 МиБ.

## Запуск

**Среда:** Zig 0.17.1, Windows PowerShell.

Открыть PowerShell в папке проекта.

**Запуск автоматических тестов:**

```powershell
zig test .\main.zig
```

**Запуск конвертера:**

```powershell
zig run .\main.zig
```

Программа считывает `input.hex` и создаёт `output.bin`.

**Просмотр бинарного результата:**

```powershell
Format-Hex .\output.bin
```

**Сравнение с эталоном:**

```powershell
Get-FileHash .\expected.bin -Algorithm SHA256
Get-FileHash .\output.bin -Algorithm SHA256
```

Совпадение хешей подтверждает идентичность файлов.

Если Zig не добавлен в `PATH`, необходимо использовать полный путь к `zig.exe`.

## Реализация

Основные компоненты:

- `Decoder.record` — разбор записи Intel HEX, проверка контрольной суммы и обработка адресов.
- `nibble`, `hexByte` — преобразование шестнадцатеричных символов в байты.
- `whitespaceTrim` — удаление лишних пробелов.
- `convert` — обработка входного файла и формирование бинарного образа.
- `main` — чтение `input.hex` и сохранение `output.bin`.
- `expectBytes` — вспомогательная функция тестирования.

Для преобразования используются стандартные возможности Zig.

## Тестирование

В программе предусмотрено 13 автоматических тестов, проверяющих:

- Обычное преобразование и заполнение пропусков.
- Расширенную сегментную и линейную адресацию.
- Проверку контрольной суммы.
- Некорректные шестнадцатеричные символы.
- Отсутствие записи завершения файла.
- Превышение допустимого адреса.
- Неподдерживаемые типы записей и повреждённые данные.

Ожидаемый итог успешного тестирования:

```text
All 13 tests passed.
```

Для тестового файла ожидаются следующие байты:

```text
01 02 03 04 FF FF AA BB
```
